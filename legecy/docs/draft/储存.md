  文件写进 volume。

  ## 3. Database 到底指什么

  “数据库”经常同时指三种不同东西：

  ### PostgreSQL 软件

  例如 image：

  postgres:16-alpine

  它只包含 PostgreSQL 程序，没有你的比赛数据。

  ### PostgreSQL 运行实例

  例如 container：

  gogg-dev-postgres

  它负责运行 PostgreSQL 进程，监听端口 55433。

  ### PostgreSQL 数据文件

  例如 volume：

  gogg-dev_pg_data

  里面才是真正的表、索引、WAL、配置和数据库文件。容器删除后，只要 volume 还在，数据通常还在。

  完整关系是：

  postgres:16-alpine
          │ 创建
          ▼
  gogg-dev-postgres 容器
          │ 挂载
          ▼
  gogg-dev_pg_data volume
          │ 包含
          ▼
  PostgreSQL PGDATA
          │ 包含
          ▼
  gogg 数据库、表、索引、比赛数据

  ## 4. Image 和 Container

  ### Image

  Image 是只读模板，类似“安装光盘”。

  postgres:16-alpine
  redis:7-alpine
  temporalio/auto-setup:1.25.2

  删除 PostgreSQL image：

  - 不会直接删除数据库 volume；
  - 但容器下次启动可能需要重新下载 image。

  ### Container

  Container 是 image 的运行实例，类似“已经安装并启动的程序”。

  你当前主要有：

  gogg-dev-postgres       应用 PostgreSQL
  gogg-dev-temporal-pg    Temporal PostgreSQL
  gogg-dev-redis          Redis

  Container 可以处于：

  - running：正在运行；
  - stopped/exited：停止了，但容器配置还在；
  - removed：容器对象已经删除。

  删除 container 通常不会删除 named volume。

  ## 5. Volume 是什么

  Volume 是 Docker 管理的持久化目录。

  项目 Compose 中声明的是：

  volumes:
    pg_data:
    temporal_pg_data:

  因为 Compose 项目名是 gogg-dev，实际名称会变成：

  gogg-dev_pg_data
  gogg-dev_temporal_pg_data

  配置见 deploy/compose/docker-compose.dev.yml:20。

  映射关系：

  gogg-dev_pg_data
      ↓
  容器内 /var/lib/postgresql/data
      ↓
  GOGG 应用数据库文件

  Volume 与 container 生命周期分离：

  删除 container     → volume 通常还在
  重新创建 container → 可以重新挂载原 volume
  删除 volume        → 数据库文件真正丢失

  ## 6. Volume 默认存在哪里

  Docker Desktop 默认把 named volumes 放在：

  docker_data.vhdx

  逻辑路径类似：

  /data/docker/volumes/gogg-dev_pg_data/_data
  /data/docker/volumes/gogg-dev_temporal_pg_data/_data

  因此：

  - 新建另一个 named volume，还是会进入同一个 VHDX；
  - volume 内删除 17 GB，ext4 内部会多出 17 GB；
  - 但 Windows 看到的 VHDX 文件不一定立刻缩小；
  - 需要完全停止 Docker Desktop 后压缩 VHDX，Windows 的 D 盘空间才可能真正增加。

  ## 7. Bind mount 和 Volume 的区别

  Named volume：

  volumes:
    - pg_data:/var/lib/postgresql/data

  数据位置由 Docker 管理，默认在 docker_data.vhdx。

  Bind mount：

  volumes:
    - type: bind
      source: /mnt/gogg-perf/postgres-16
      target: /var/lib/postgresql/data

  数据位置由我们指定。旧测试库就是这种方式，配置见 deploy/compose/docker-compose.perf-drive.yml:20。

  所以技术上，数据库可以独立放到另一个 ext4 磁盘/VHDX，不必和 images 一起迁移。

  但是不能直接把 PostgreSQL PGDATA 放到 E 盘 exFAT 目录，例如：

  /mnt/e/gogg/postgres

  更合适的是：

  E:\gogg-data\gogg-db.vhdx
          ↓ 内部 ext4
  /mnt/gogg-db
          ↓
  /mnt/gogg-db/postgres

  这样只是创建一个 VHDX 文件，不会格式化整个 E 盘。

  ## 8. /postgres-16 是什么

  它是旧性能测试数据库的 PGDATA 目录：

  /postgres-16

  里面曾经包含：

  PG_VERSION
  base/
  global/
  pg_wal/
  pg_stat/
  ...

  它不是：

  - Docker named volume；
  - image；
  - container；
  - PostgreSQL dump。

  它只是一个保存完整 PostgreSQL 数据文件的目录。

  从 Docker Desktop 的视角，它的完整路径是：

  /mnt/docker-desktop-disk/postgres-16

  之前占用约 17 GB，现在已经删除。

  ## 9. gogg-perf-postgres 是什么

  它是旧性能测试数据库的 container：

  gogg-perf-postgres

  关系是：

  postgres:16-alpine image
          ↓
  gogg-perf-postgres container
          ↓ bind mount
  /postgres-16 数据目录

  删除时我们做了两件事：

  1. 删除 gogg-perf-postgres 测试容器；
  2. 删除 /postgres-16 数据目录。

  但保留了：

  /snapshots/rankings-kr-16.13-current-v1/database.dump

  因此旧测试数据仍可从快照恢复。

  ## 10. /mnt 是什么

  Linux 中 /mnt 通常用来挂载其他磁盘或文件系统。

  ### /mnt/c、/mnt/d、/mnt/e

  这是 WSL 对 Windows 盘符的映射：

  C:\  → /mnt/c
  D:\  → /mnt/d
  E:\  → /mnt/e

  例如：

  E:\backup\collector-bundle-all-20260826.tar

  在 WSL 中是：

  /mnt/e/backup/collector-bundle-all-20260826.tar

  ### /mnt/gogg-perf

  这是人为创建的挂载点。

  没有挂载磁盘时，它只是 Ubuntu 里的一个普通空目录。挂载 ext4 磁盘后：

  /dev/某设备 → /mnt/gogg-perf

  里面才会显示真实磁盘内容。

  这也是为什么脚本必须检查：

  - 它是不是挂载点；
  - UUID 是否正确；
  - 是否可写。

  否则外置盘没有挂上时，程序可能误把数据库写回 Ubuntu 的 D 盘。

  ### /mnt/docker-desktop-disk

  这是 Docker Desktop 自己的 WSL 环境里，docker_data.vhdx 的挂载位置。

  同一份数据可能因为观察位置不同而有不同路径：

  Docker Desktop 内：
  /mnt/docker-desktop-disk/postgres-16

  挂载给 Ubuntu 后：
  /mnt/gogg-perf/postgres-16

  容器内：
  /var/lib/postgresql/data

  三条路径可以指向同一份数据。

  ## 11. 删除不同对象的后果

   删除对象                  结果
  ━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   删除 stopped container    删除容器配置和可写层，volume 通常保留
  ────────────────────────  ──────────────────────────────────────────────────
   删除 image                以后需要重新下载或构建，volume 不受影响
  ────────────────────────  ──────────────────────────────────────────────────
   删除 build cache          下次构建较慢，业务数据通常不受影响
  ────────────────────────  ──────────────────────────────────────────────────
   删除 Redis volume         缓存、会话或限流状态丢失
  ────────────────────────  ──────────────────────────────────────────────────
   删除 PostgreSQL volume    数据库文件永久丢失
  ────────────────────────  ──────────────────────────────────────────────────
   删除 docker_data.vhdx     所有 Docker images、containers、volumes 一起丢失
  ────────────────────────  ──────────────────────────────────────────────────
   删除 Ubuntu ext4.vhdx     Ubuntu、代码、归档和备份一起丢失
  ────────────────────────  ──────────────────────────────────────────────────
   删除 database.dump        对应恢复备份丢失
  ────────────────────────  ──────────────────────────────────────────────────
   删除 bundle tar           原始采集归档丢失，但已导入数据不一定立即受影响

  最重要的三句话：

  1. Image 是程序模板，container 是运行实例，volume 才是持久化数据。
  2. docker_data.vhdx 是装着 Docker 大部分 Linux 数据的虚拟硬盘文件。
  3. 数据库可以单独放到 E 盘，但应放在 E 盘上的 ext4 VHDX 内，不能直接把 PostgreSQL 数据目录放到 exFAT。
