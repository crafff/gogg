# 学习、经验晋升与评测

状态：v2 提案。入口：[总览](../agent-system-design.md)。

## 1. 系统可以学什么

| 层次 | 被改变的对象 | 本设计的处理 |
|---|---|---|
| 事实学习 | 已核实契约、环境与失败条件 | 证据核实后更新版本化知识 |
| 程序学习 | 检索方法、Skill、验证流程 | 独立任务评测后晋升 |
| 工具/执行策略学习 | 工具包装、任务分解、上下文策略 | 隔离实现、故障测试和消融后晋升 |
| 模型参数训练 | 模型权重 | 独立研究项目，不作为 Codex 自带能力 |

外部经验影响后续上下文和工具执行，并不改变基础模型。成功经验和失败反思都
可能带有错误；系统只承诺可追溯改进过程，不能承诺每次学习都进步。

ACE 使用带 ID 的增量修改和反思/整理角色，研究也展示有害反思会污染上下文。
DGM 在冻结模型的前提下搜索工具与流程变体，附录记录指标投机。因此借鉴候选
档案、反思和受控搜索，同时将评价器与晋升权独立保护。
[ACE v3](https://arxiv.org/html/2510.04618v3)、
[DGM v3](https://arxiv.org/html/2505.22954v3)

## 2. 学习流水线

```text
真实轨迹与证据
  → 归因：需求/知识/代码/工具/环境/验收哪里失败
  → 候选：修改哪一条知识、哪一步流程或哪个工具
  → 可复现反例与适用范围
  → 隔离评测：旧版/候选版配对运行
  → 回归与未见任务
  → 独立审查、接受与版本发布
  → 后续任务观察，发现回归可回退
```

一次成功可证明该次运行完成，不能直接证明抽象出的技能能泛化。
事实晋升和技能晋升不同：事实核实来源与条件；技能证明在其他适用任务上有用。
学习候选记录 `candidate_id / origin_runs / failure_class / proposed_delta /
applicability / evaluator_revision / baseline_release / evaluation_runs /
decision / rollback_target`。

维护者向单一条目或技能提交小补丁，不整本重写记忆。合并保留源 ID 和证据；
Git 文本合并成功不代表语义冲突已解决。命中次数、有用/有害计数和 LLM 信心
只用于筛查，不能成为晋升的充分条件。

## 3. 权限与修改边界

学习者可提出知识、Skill、检索和工具候选，在独立实验工作区运行。候选不能
修改原始验收、隐藏测试、授权规则或用来评分自己的记录。强制指导与权限变化
需要独立的工程任务和相应授权；不得从网页、日志或一次失败自动推导新权限。

持久流程运行期间固定 `release_id + knowledge_snapshot_id`，分别锁定执行组合
和知识内容/状态/来源/检索配置；gate 也绑定两者。新候选在新任务启用。用户当前纠正优先于快照，
主控显式修订契约并重新检查受影响关卡，不后台静默替换输入。

学习器拿到经脱敏、限量的证据包；完整私人会话和玩家资料不默认共享。
外部资料、仓库文档、工具输出和子 Agent 结论都可含不可信内容，存放位置不提高
指令优先级。禁止多个 Agent 投票把同一未经核实资料提升为事实。

## 4. 评测分三类

| 评测 | 衡量什么 | 典型任务 |
|---|---|---|
| 代码工作 | 能否完成复杂变更并少遗漏 | 终态、幂等、生成链、用户重连、性能回归 |
| 记忆/检索 | 能否找到且正确使用当前有效证据 | 跨分支、过期契约、冲突、未知、引用追溯 |
| 长期系统 | 多次任务与中断后是否可靠 | 崩溃、重放、取消、并发认领、备份恢复、版本升级 |

先从真实 GOGG 问题建立小型可运行基线，再按任务族扩充。起步建议约 12–20 个
端到端任务与 30–50 个知识问题；这是测试覆盖规划，不是统计充分性保证。
长期验收需要随后数周连续任务的数据，短样本不能宣称全面优于原系统。

## 5. 防止回放泄漏

历史任务恢复当时的代码、规则、可见测试和知识。工作副本不能带后来修复的 Git
对象或 refs；评分答案、后来的测试和修复提交放在独立评分环境。
关闭评测运行的原生 Memories 使用与生成，不删除用户已有记忆。
“使用当前项目经验”的能力另设实验组，不与无未来知识的能力比较混报。

隐藏评测不是在同一仓库建一个不常读目录。评分服务使用不同权限主体或隔离
容器，候选运行时不挂载答案、评价器实现和相应凭据。可见测试可由 Agent 扩展，
验收 oracle 从受保护的固定版本执行，不能信任候选修改后的同名脚本。
模型可能见过公开题的风险另行记录，优先补充未公开、时间后移的项目任务。

开发集用于修改候选；验证集用于选择；保留集只用于受控发布评估。反复在同一
保留集挑选会泄漏信号，记录访问次数并轮换新增任务，不向学习者披露隐藏答案。

## 6. 质量优先的比较

固定当前最强模型、工具权限、环境和数据，比较：

1. 无增量经验的基础流程。
2. 当前已发布的知识与技能组合。
3. 仅改变一个主要机制的候选组合。

随机性明显的任务做配对重复，报告分布、失败样例和样本数。模型升级时固定
流程单独比较，再评估是否移除为旧模型补弱的机制。
不同时更换模型、检索、提示和评分后把提升归因于“记忆系统”。

首要指标是完整验收、严重回归、错误知识采用、跨分支误用、未知时恰当保留、
恢复正确性和人工纠正。正确性达标后再比较时间、调用数、token 和工程维护成本。
质量优先不以昂贵调用数量衡量；重复无增益的工作可能扩大错误而非增加质量。

候选发布至少要求必需测试通过、没有未解决阻断问题、针对目标失败有改善证据，
且重要任务族没有不可接受回归。具体统计阈值由基线与任务风险定义，不先编一个
通用通过率。主观 UX 使用明确 rubric、真实用户/专家与独立审查，LLM 评分只补充。

## 7. 可选优化器和发布

GEPA 官方实现可以接收文本候选及外部 evaluator，适合后续离线优化 Skill、
检索描述和任务策略。先做可信评价器，再引入优化器；搜索预算、候选数、测试
访问和外部调用可审计。一次优化也不能自行发布或改评测。
[GEPA 官方实现](https://github.com/gepa-ai/gepa)

发布文件固定 `model / effort / guidance_hashes / skill_revisions /
knowledge_snapshot_id / workflow_revision / adapter_revision /
dependency_lock_digest / checkpoint_schema_version / execution_schema_version /
toolchain / index_schema / evaluator_revision / accepted_evidence /
fallback_release / fallback_knowledge_snapshot_id`。模型别名不能当永久快照；记录实际可取得的版本信息，不
假设提供方允许永久固定底层权重。升级需要重新验证。

回退恢复上一套知识/工具/流程版本，不等于删除新任务的证据。旧运行使用原
版本完成或显式迁移，避免中途换规则。LangGraph checkpoint 不包含旧节点的
可执行实现，旧运行需要匹配的可取得运行时；版本或 schema 不兼容时先暂停并
迁移，不能用新代码盲目恢复。学习器自身升级同样需要独立评价。

## 8. 建议优先的 GOGG 试点

- 新会话正确恢复一个含未提交文件的任务。
- 已知终态不会进入重试；错误状态不会被“通过”文本掩盖。
- 修改相关实现后，旧知识停止自动成为当前事实。
- 并行候选修改生成链，旧审查结果被拒绝。
- 统计结论存在数据泄漏或不支持因果时，Agent 明确指出并修改实验。
- 固定数据下性能测量不受并行构建污染。
- 一个失败教训转为技能后，能帮助另一个未见的同类任务。
- 评分器、索引、hook 或模型不可用时，不绕过必需验收。
