# 阶段 5：API 正确性与资源保护

本文件是阶段入口；资源上限和保护方案在开展后添加到本目录。

## 目标

通过输入边界、分页、超时、限流和并发控制，防止合法或恶意请求耗尽服务资源。

## 步骤

1. 非法数字、position、tier 和 version 返回稳定的 `400`。
2. rankings 不暴露客户端 `limit`，始终返回有限英雄集合，并固定 500 行安全上限。
3. 其他可能无界增长的大列表使用 cursor pagination。
4. 设置请求体、Header、读取、写入和处理超时，并确保取消传递到依赖。
5. 对 OAuth、token 刷新和高成本查询使用差异化限流。
6. 增加最大并发与连接池保护，统一 REST 错误结构。

## 验收标准

- fuzz 和边界测试不能触发无限结果、panic 或无界分配。
- 超时会取消 PostgreSQL 和 Redis 操作。
- 限流响应状态码和重试信息稳定。
- 所有资源上限都有配置、默认值、指标和测试。
