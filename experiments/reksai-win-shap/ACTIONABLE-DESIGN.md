# 面向训练建议的雷克塞分析重设计

## 目标变化

旧问题是“15 分钟局势能否预测胜负”，所以相对经验和经济差自然占据首位。新问题是：

> 在相近玩家水平、阵容、版本和窗口初始局势下，某项玩家可练习行为达到什么水平，与多少额外胜率相关？

输出不再是单一 SHAP 排名，而是训练卡片：

```text
指标：10 分钟野怪数
建议区间：65→70
调整后胜率变化：+x.x pp（95% CI ...）
适用人群：KR 翡翠至大师、16.14、雷克塞打野
样本/重叠性：...
证据等级：调整后观察性关联 / 稳健的准因果估计
```

## 分析单元与时间窗口

为每局建立 5、10、15 分钟三个 landmark 数据集。每个数据集只能使用该分钟及之前发生的信息预测最终胜负。

行为效果分析采用窗口：0→5、5→10、10→15。估计某窗口行为时，只用赛前变量和窗口开始时的局势控制混杂，不能控制窗口结束后的经济、经验等中介变量。

例如估计“5→10 分钟成功抓人参与次数”的效果时：

- 可控制：版本、地区、段位、双方阵容、玩家历史雷克塞水平、5 分钟等级/经济/位置/血量等；
- 处理/练习指标：5→10 分钟击杀参与、抓人路线或刷野数；
- 不可控制：10 分钟经济/经验差，因为它可能正是抓人影响胜率的路径。

## 应采集的可练习指标

### 刷野与发育效率

- 5/10/15 分钟野怪数及每分钟增量
- 0→5、5→10、10→15 的野怪数
- 敌方野区野怪数（需要 Riot timeline participant frame 对应字段支持并持久化）
- 回城前持有经济、回城次数、两次购买间隔
- 死亡造成的不可行动时间

建议阈值候选：10 分钟 50/55/60/65/70 野怪，必须检查每个阈值两侧样本量，不能只报告最漂亮的点。

### 抓人与战斗

- 5/10/15 分钟击杀、死亡、助攻
- 击杀参与次数和击杀参与率
- 首次成功击杀参与时间
- 各窗口成功击杀参与次数
- 对英雄伤害、承伤、控制时间
- 抓人后的死亡率、资源转换率

仅凭现有 Riot timeline 可以可靠计算“成功击杀参与”，不能可靠识别没有产生击杀的失败抓人。因此产品中应称“成功抓人/击杀参与”，不能笼统称“抓人次数”。

### 地图资源与转换

- 先锋、小龙、巢虫参与及发生时间
- 击杀参与后 90 秒内获得塔皮、塔或中立资源
- 5/10/15 分钟前塔皮、推塔参与
- 首塔发生时间与雷克塞是否参与
- 插眼、排眼及关键河道/敌方野区位置（需要事件坐标）

### 路线与技能

- Q/W/E/R 加点顺序
- 第一次与第二次回城时间
- 核心装备/组件首次购买时间
- 5→10、10→15 分钟位置区域序列，而不是两个时点的直线位移

## 当前存储缺口

当前 `match_participant_snapshots` 已支持经济、补刀、等级、经验、位置、控制、视野和伤害快照；`match_item_events` 与 `match_skill_events` 支持购买和加点。

抓取 DTO 已解析部分 `CHAMPION_KILL`、`BUILDING_KILL` 字段，但 phase5 没有持久化它们。中立资源事件字段也尚不完整。因此下一步需要新增通用事实表：

```sql
match_timeline_events (
  match_id, timestamp_ms, event_type,
  actor_participant_id, victim_participant_id,
  assisting_participant_ids,
  team_id, killer_team_id,
  monster_type, monster_sub_type,
  building_type, tower_type, lane_type,
  pos_x, pos_y
)
```

并为 `(match_id, timestamp_ms)`、`(match_id, actor_participant_id, timestamp_ms)` 建索引。抓取时应保存英雄击杀、精英野怪击杀、建筑击杀、塔皮、插眼和排眼事件。事件解析与写入应使用新 migration，不能依赖目前无人写入的 `match_timelines.raw_events`。

另外需要从历史对局滚动计算玩家赛前能力特征，且严格只使用当前比赛之前的数据：雷克塞场次、历史胜率、历史 10 分钟刷野、段位及近期状态。它们用于控制“强玩家本来就更容易同时刷到 70 刀和获胜”的混杂。

## 推荐分析方法

### 第一层：EBM 阈值发现与描述

使用 Explainable Boosting Machine（可解释的广义加性模型）代替 LightGBM + SHAP 作为主展示模型：

- 每个特征直接得到一条 `指标值 → log-odds/胜率贡献` 曲线；
- 能发现 60→65 有收益而 70 以后趋平等非线性阈值；
- 限制少量二阶交互后仍可解释；
- 对每条曲线做玩家级 bootstrap 置信带；
- 按版本、地区、分段做留出稳定性验证。

EBM 曲线仍是调整后的预测关联，只负责发现候选阈值，不写成因果结论。

### 第二层：候选训练动作的增量效果

对少数候选问题预注册处理变量，例如：

- `10 分钟野怪数 >= 70`；
- `0→10 分钟成功击杀参与 >= 2`；
- `10 分钟前参与首个中立资源`；
- `击杀参与后 90 秒内转换出地图资源`。

使用 cross-fitting 的 AIPW / Double Machine Learning 估计平均处理效应，倾向模型和结果模型使用灵活学习器。报告：

- 调整后的胜率差（百分点）和 95% 置信区间；
- propensity overlap 和有效样本量；
- 玩家分组 bootstrap；
- 不同版本、地区、分段的重复结果；
- 未测混杂敏感性分析。

如果需要回答“哪些玩家更适合抓人而非刷野”，再使用 causal forest 估计异质处理效应；不应把 causal forest 当作第一步的全自动特征排名器。

### 为什么不继续只用 SHAP

SHAP 回答“模型为什么这样预测”，不回答“玩家改变该指标后胜率会增加多少”。经济差、经验差是典型的强预测状态和潜在中介变量。将它们排第一对预测完全正确，但不能直接生成训练处方。

## 验证与发布门槛

1. 玩家级且时间外切分：用旧版本训练，新版本测试。
2. 每项建议至少在两个版本、两个地区方向一致。
3. 阈值两侧均满足预先规定的样本量和 propensity overlap。
4. 同时报告未调整胜率、EBM 调整关联和 DML/AIPW 估计，三者不得混称。
5. 多阈值搜索进行验证集确认或多重比较校正。
6. 教学文案优先描述行为，不描述结果状态；“10 分钟刷到 65–70 野”可以，“建立经验领先”不能单独作为建议。

## 实施顺序

1. 新增并回填 timeline event 事实表。
2. 构建 5/10/15 分钟行为宽表及玩家历史能力特征。
3. 用 EBM 生成阈值曲线和分组稳定性报告。
4. 预注册 3–5 个候选动作，使用 AIPW/DML 估计增量胜率。
5. 经版本外验证后再生成面向玩家的训练卡片。
