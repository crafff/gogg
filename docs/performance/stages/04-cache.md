# 阶段 4：优化缓存

## 目标

在保证数据可见性和降级能力的前提下提高命中率，并防止缓存失效造成数据库风暴。

## 步骤

1. 增加业务级 cache hit、miss、error 和 loader duration 指标。
2. 验证 cache key 包含全部过滤条件和 schema 版本。
3. 配置 TTL 与随机抖动，定义允许的数据陈旧时间。
4. Worker 发布数据后主动失效相关排名缓存。
5. 验证 `singleflight` 下并发 miss 只触发一次数据库加载。
6. 验证 Redis 延迟、不可用、loader 失败和大响应值。
7. 必要时评估 stale-while-revalidate，并明确一致性语义。

## 必测场景

- 热缓存稳定负载、单 key 冷启动、多 key 同时过期。
- Redis 高延迟及完全不可用。
- loader 失败不缓存错误结果。
- 大 value 对 Redis 内存、序列化和网络的影响。

## 验收标准

- 命中率达到目标且能由流量结构解释。
- Redis 故障不导致全部 API 失败，回源并发受控。
- 缓存失效不形成数据库请求风暴。
- 新数据在约定时间内可见。
