# GOGG delivery

Read `engineering/README.md` and the relevant task contract. Derive observable acceptance
from the current user request and capability baseline; archived implementation is evidence,
not an architectural constraint or authorization to start archived services.

Track the primary outcome, assumptions, dependencies and current slice. Delegate bounded
independent exploration or review when useful; specify inputs, file ownership and expected
evidence. Keep one writer per file set and explicitly coordinate generated/shared interfaces.

Before verification, identify the candidate including uncommitted and required untracked
files. Keep data, environment and evaluator revisions with the result. A code or contract
change invalidates affected previous results; document unavailable checks as gaps.

For recovery/data changes verify terminal, retry, cancellation and duplicate paths. For UX
verify a real user flow and failure state. For performance use a fixed load with competing
builds/indexing paused. Broaden tests in proportion to remaining risk, not by ritual.

At handoff report outcome, evidence, remaining risk and any proposed durable knowledge.
`make check` verifies the current engineering foundation, not the future website.
