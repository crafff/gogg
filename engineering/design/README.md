# GOGG 长期研发 Agent 体系：v2 设计入口

2026-09-04 设计，2026-09-05 UTC 迁入新工程。状态：长期目标设计。
原生指导、角色、知识工具和归档基础开始实施；持久工作流与自动学习尚未实施。
实际状态以 [研发入口](../README.md) 和 [迁移记录](../migrations/2026-09-05-clean-rebuild.md) 为准。

目标是建立可长期维护、可恢复、能从证据中积累经验的研发体系，支持 GOGG
保留现有 LoL/TFT 能力，持续发展个性化推荐、取胜因素分析与玩家提升功能。
用户要求质量优先；关键研究、规划、实现、验证、审查和经验提炼统一优先使用
当前最强可用模型 Astra，不再以降低模型成本为默认分工依据。

## 核心选择

- Codex 与 Astra 负责代码工作，LangGraph 作为外层持久工作流的优先候选。
  采用前先验证取消、恢复、审批和副作用语义；原生 Codex 可单独承担初期试点。
- 一个主 Agent 对目标负责，专家按证据需求启动；同一文件集有唯一写者。
- Git 保存规则、知识与契约；持久工作流保存执行进度；不可变制品保存证据；
  检索索引只做派生视图。
- 学习产生可审查的知识、技能或工具候选，通过独立评测才进入默认流程。
- 研发经验、玩家个人数据、历史业务数据集分别管理。
