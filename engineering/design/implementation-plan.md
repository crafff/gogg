# 落地、迁移与长期维护计划

状态：长期路线图，以下阶段不会自动代表已完成。当前引导实施结果以
[迁移记录](../migrations/2026-09-05-clean-rebuild.md)为准。入口：[总览](README.md)。

## 1. 设计研究轮次的已完成与未完成（历史状态）

已完成：当前 Codex 能力核实、两条 Astra 研究通道、v2 文档组织、存储与维护设计、
竞品公开能力核对和设计审查。v1 保留为历史归档。
未完成：运行时安装、模型默认切换、知识迁移、索引实现、学习候选实验、完整竞品
交互测量、网站重构或产品性能验证。设计不能作为这些项目的通过证据。

## 2. 阶段 A：能力契约和知识整理

交付：产品 capability 清单、工程目标与质量原则、知识类型/schema、源文档迁移
映射、任务/证据契约，以及最强模型角色配置的具体候选。

将旧归档中的指导、项目事实和 ADR 按需提炼到当前权威来源。迁移逐条记录
`旧位置 → 新位置 → 保留/合并/待核实/历史归档 → 证据`。
本次已保存含未提交变更的完整旧树；后续提炼以该已保存版本为来源，不能只从旧
HEAD 获取材料而遗漏未提交内容。个人原生记忆不在本次迁移写入范围。

根结构已切换，旧目录完整保存在legecy。继续核实能力与知识覆盖和引用，不重新
启用旧入口或让两份正文共同拥有当前事实。
强制指导变更、角色配置和模型切换在新运行中验证有效加载，不能只检查文件存在。

退出条件：原有规则与能力无遗漏；新会话能找到正确资料；未知和过时事实明确；
模型实际值、推理、角色和权限符合质量策略。

## 3. 阶段 B：原生 Codex 试点和评测基础

交付：少量真实端到端任务、知识问答、独立评分协议和候选/证据 manifest。
任务先原生执行，记录主控、专家、恢复和审查；不要求先完成整个自研平台。
以质量为首要指标，确认知识与独立验收的增量价值。

试点必须包含含未提交文件的恢复、过时知识、错误终态/重试、生成漂移、一个
浏览器流程、一个性能场景，以及统计解释不充分的情况。补真实失败驱动的测试，
不写仅验证目录存在或复述实现的形式测试。

退出条件：任务输入、候选与结果可追溯；验证能识别已知错误；未来知识/隐藏测试
没有泄漏；可以清楚报告未验证项和工具限制。

## 4. 阶段 C：持久工作流和受控自动化

优先试点 Python LangGraph + 官方 Python Codex SDK。实现适配器、阶段图、
执行账本、资源所有权、制品存储和版本化 gate；框架负责通用 checkpoint/恢复，
领域代码负责工作区、进程和操作核对。先验证组合，再固定依赖版本。
SQLite 仅承担本地试点；长期运行验证 PostgreSQL 持久后端及工程/业务数据隔离，
保留框架字段与领域账本的唯一所有权。检查后端迁移与 checkpoint 保留规则。

流程与动作账本各有唯一字段所有权，测试跨存储中断窗口。后台任务包含知识
维护和受控学习，和产品开发共享队列但有资源优先级。
hooks 只桥接上下文和检查，不替代核心关卡；不可用时显式入口仍能执行验收。

退出条件至少包括：节点重放不重复启动写者、旧 lease/incarnation 不能写入或
接受结果、取消与接受冲突可裁决且子进程确实停写、未知操作先核对、缺失制品
不能通过、状态备份能恢复未完成任务、受限证据无法经索引或引用越权读取。
性能记录区分框架开销、Codex 模型调用、编译测试和业务服务。

## 5. 阶段 D：经过验证的学习

交付：失败归因、候选知识/Skill 变更、隔离评价器、保留集、发布/回退清单。
先人工定义少量可解释候选，证明改进闭环有用，再引入 GEPA 等离线优化器。
优化器不得读取隐藏测试或修改评分器；模型权重训练另立研究任务。

退出条件：至少一个候选帮助未见同类任务，关键回归未恶化；错误经验被拒绝；
版本回退可恢复旧流程；评价器和制品未受候选篡改。

## 6. 阶段 E：持续运行和多机执行

在数周真实任务上记录遗漏、人工纠正、恢复、知识命中与污染情况，按失败归因
调整系统。跨机器仅在需要更多隔离执行容量或可用性时开展，网站多机与 Agent
多机分别决策。控制服务唯一，远端 worker 交换明确版本的制品，不共享可变工作区。

退出条件：断网/执行者丢失/重复请求/接管演练通过，备份在另一故障域恢复，
资源竞争不破坏产品基准。没有这些证据时不宣称可长期无人值守。

## 7. 日常维护职责

| 责任 | 所有者 | 产物 |
|---|---|---|
| 当前目标、范围和验收 | 主 Agent 与用户要求 | 契约 revision |
| 执行状态、租约、进程 | 唯一控制服务 | checkpoint 与执行事实 |
| 共享知识 | 指定维护者串行整合 | 知识补丁、冲突与失效记录 |
| 工程关卡 | 版本化评价器与独立审查 | 候选绑定的 gate 结果 |
| 模型、框架与技能升级 | 受控升级任务 | 配对评测、接受和回退版本 |
| 备份、索引、容量 | 维护作业 | 恢复报告、重建结果、清理计划 |
| 推荐和玩家效果 | 独立产品研究流程 | 数据/模型/实验协议与用户结果 |

后台维护频率按事件和实际任务量确定；用户当前任务优先，资源重型维护不得影响
性能测量。仅明确授权的清理政策可删除对象，业务档案不交给 Agent 缓存回收。

## 8. 架构仍需试点回答的问题

- LangGraph 与当前 Codex SDK 的取消、审批、线程重接在本宿主是否可靠？
- 最强模型配独立角色是否改善本项目完整验收，哪些角色需要共享/独立上下文？
- 文件路由与 FTS 是否足够，语义或图索引的增量价值在哪里？
- 哪些经验可泛化，哪些只适用于某个补丁、数据集、角色或环境？
- 真实单机硬件、数据量与用户任务下，网站和研发体系各自的资源预算是多少？

这些是实施阶段的有界实验，不妨碍先完成已明确的契约、迁移映射和评测准备。
