# 任务契约与接续

从当前用户要求选择或建立 `任务目录/contract.json`，不要把历史 bootstrap 当作
新工作的授权或验收。每份契约包含 `schema_version: 1`、稳定 `id`、`status`、
`objective`、`authorization`、`out_of_scope`、`acceptance`。

契约的 `status` 是任务接续的唯一状态字段：最多一份为 `active`，结束后改成
`completed` 并保存同目录的 `outcome.md`。`make foundation-check` 输出活动契约，
没有活动任务时应从新要求建立下一份；不维护另一份“当前任务”链接或实时进度表。
当前步骤由执行中的计划记录，历史结果只描述当时的候选与验证，不代表后续版本。

结果记录至少说明范围、候选身份、实际命令与环境、结果和未验证项。未提交候选
可在结果中列出受检文件的内容摘要；摘要清单排除清单与结果文件自身，避免循环绑定。

首个产品重构任务需引用[能力基线](../charter/capabilities.md)，为本切片适用的
能力 ID 写出固定输入、可见结果、关键失败场景和验收方式。全局未盘点项继续
登记，删减或延期明确决定；无需先实现全部网站或长期 Agent 平台。
